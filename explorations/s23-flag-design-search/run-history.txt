Draft before the first run (not a recorded run): the first draft of the script contained a leftover no-op loop in the family builder and a layered-count check that ended in "or True" and so could not fail.
  Both were removed before any run; the check now asserts the real idle-location counts (20 and 32 layered against 40 and 84 serial for J conv and J flag) and the depths 7 and 9.

First full run: all checks passed except A4, which FAILED, and B2 passed for a wrong reason.
  A4: I had written the smallest M2 second-order coefficient as 47/30 after reading 1.564 off a decimal print.  The exact value is 352/225 = 1.5644 (47/30 = 1.5667).  The check compares exact fractions,
      so it failed, correctly.  The docstring and the check now carry 352/225; V1.0's 58/25 = 2.32 was right.
  B2: the bisection for the measurement-layer duration m that reproduces the 1.0496e-3 crossing was bracketed on [5, 6] and returned 6.000, which is the edge of the bracket, not a solution
      (the crossing at m = 6 is 1.0630e-3, still above 1.0496e-3).  My acceptance window 5.9 < m < 6.2 would have passed the clipped value.  The bracket is now [5, 8], the window is 6.0 < m < 6.1,
      and the printed value is 6.041.

Second run: A4 still failed because the replacement of the text "47/30" did not reach the exact comparison Fr(47, 30) in the code; that was changed too.

Final run: ALL PASS (see execution-record.txt).  Nothing in the results other than those two constants changed between runs.
