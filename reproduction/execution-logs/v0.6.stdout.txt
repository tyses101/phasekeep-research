== 2. check-sliding ==
PASS  the parity extraction is exactly U_ext = P_even (x) 1 + P_odd (x) X_ancilla: it depends on the data only through the parity observable ZZ
PASS  an ideal check slides past any gate that commutes with ZZ, on arbitrary inputs including odd components: rot(ZI), rot(IZ), rot(XX), XX gate
PASS  it does NOT slide past gates that do not commute with ZZ: X on one axis, rot(XI), CNOT(a->b), H on one axis
PASS  sliding is exactly the commutation condition: check-then-gate equals gate-then-check for these gates if and only if the gate commutes with ZZ
PASS  with compatible steps only, a check at position p detects a single flip exactly when the flip occurred before p (a later check covers more of the sequence): sliding changes WHICH faults are covered even though it does not change the ideal outcome
PASS  with a CNOT in the sequence the check has to be MOVED, not slid: the valid check after the CNOT is Z on axis b. A flip on axis a made BEFORE the CNOT is detected at every later position by the moved check; the same flip made AFTER the CNOT is not detected (axis a now carries the qubit); a flip on axis b is detected either way. Coverage depends on where in the sequence the fault occurs
PASS  a check left as ZZ after the CNOT would read 0.00 to 0.99 on fault-free states (amplitude-dependent): the old check is not a check of the new code
== 3. error propagation ==
PASS  the damage an error does (overlap of the faulty output with the ideal output) is unchanged by any unitary that follows: propagation changes the FORM of an error, not its size
PASS  through steps that commute with ZZ, an error that anticommutes with ZZ (detectable) still does afterwards, and one that commutes still does (all 16 two-axis Paulis, three composite steps)
PASS  relative to the TRANSPORTED check G ZZ G^dagger, detectability is preserved by every unitary step, including the CNOT and the single-axis Hadamard (anticommutation survives conjugation): what changes is which check has to be read, and the single-axis Z check after a CNOT is a different extraction circuit from ZZ
PASS  a logical Z fault carried through a logical X rotation by theta becomes cos(theta) Z_L +/- sin(theta) Y_L: still undetected by ZZ (commutes), still logical, but a Pauli only when theta is a multiple of pi/2
PASS  limit of the version 0.5 chain model, stated plainly: it treats a fault as a Pauli frame that stays a Pauli. That is exact for Clifford segments and idle segments and is NOT exact for generic logical rotations (above); the comparison between spacings in version 0.5 is for Clifford or idle segments

== 6. mathematical conditions for concurrent verification ==
PASS  the extraction unitary is the exponential of a Hamiltonian that depends only on ZZ and on the ancilla (exp(-i pi P_odd (x) P_minus) = 1 - 2 P_odd (x) P_minus = U_ext)
PASS  a gate generated by a Pauli-string Hamiltonian commutes with the check Hamiltonian exactly when it commutes with ZZ: ZI: yes, IZ: yes, ZZ: yes, XX: yes, XI: no, IX: no, XY: yes, YY: yes
PASS  when the two generators commute, applying them together and one after the other give the same unitary (exp(-i(A+B)) = exp(-iA) exp(-iB)); when they do not, the combined evolution differs by terms of the commutator, so 'check during the gate' is not the same operation
PASS  these conditions are NECESSARY for ideal concurrent verification and say nothing about hardware: the check and the gate still act on the same axes, and the parity interaction, its readout and its faults are not modelled
