# Checkpoint V0.5: repeated checkpoints, reusable ancilla, routers

**Status: working development record, 2026-11-27. Index page for an original checkpoint.** Original files: [README](../../../checkpoints/v0.5/README.md), [page](../../../checkpoints/v0.5/docs/buddy-verification-v0.5.md), [handoff](../../../checkpoints/v0.5/CODEX_HANDOFF.md), [code](../../../checkpoints/v0.5/code/buddy_v05_checks.py).

## Question

What happens when verification is repeated along a computation, when one ancilla serves many photons, and what is the difference between detecting, rejecting and correcting?

## Model and assumptions

The V0.4 diagonal encoding with a parity ancilla; independent X and Z faults on two data axes, an ancilla X fault, a harmful ancilla Z fault between the CNOTs, and loss in the interaction. All rates are [ASSUMED] examples. Resource classes (selectable helper types) are [PROPOSED].

## Results [DERIVED in the model]

- A chain of checkpoints reproduces the V0.4 single-checkpoint model exactly; spacing matters.
- With ideal reset, ancilla reuse changes nothing. Without reset the ancilla reports combined parity, half of all photons are rejected whatever their quality, and flips can cancel.
- In a parity router with loss, silence is not PASS: the probability that a continuing photon is good falls below 1 as soon as loss exists.
- The two-axis parity code detects single flips but cannot correct them. A three-axis repetition code with two checks corrects single flips and gives no phase protection.
- A closed form gives how long a correct, verified state stays correct.

## Negative results

Checking every segment can accept fewer correct runs than no checking, because two flips on one axis in different segments cancel and an intermediate check rejects a run that would have come out right. Checking only after the sensitive segment is worse than checking only at the end in the examples.

## Corrections

V0.4's "never gives more correct results per run" is specific to rejection-based Pauli models and does not apply to error-correcting architectures (V0.5 section 3). V0.4 is preserved unchanged. See [Errata](../errata.md).

## Limits

Independent Pauli faults; no correlated noise, leakage or readout error beyond the ancilla X fault; reuse modelled as a steady-state stream; router results are probabilities of events, not an optical model.
