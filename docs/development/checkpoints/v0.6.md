# Checkpoint V0.6: is a check compatible with how the operation is implemented?

**Status: working development record, 2026-11-27. Index page for an original checkpoint.** Original files: [README](../../../checkpoints/v0.6/README.md), [page](../../../checkpoints/v0.6/docs/buddy-verification-v0.6.md), [handoff](../../../checkpoints/v0.6/CODEX_HANDOFF.md), [code](../../../checkpoints/v0.6/code/buddy_v06_checks.py).

## Question

Does the way a logical operation is implemented decide whether a check can run alongside it, and how should checks be placed and spaced?

## Model and assumptions

Diagonal encoding, check ZZ, parity ancilla; ideal unitaries and independent Pauli faults with [ASSUMED] example rates. A "class" is always relative to a stated check.

## Results [DERIVED]

- Two implementations of the same logical operation can differ in verification compatibility. A Hadamard built from rotations generated by ZI and XX never leaves the code; a Hadamard built from CNOT, H, CNOT leaves it midway, where a fixed ZZ read is amplitude-dependent and a transported check is the valid one.
- An ideal check slides past a gate exactly when the gate commutes with ZZ.
- Damage size is invariant under later unitaries, and detectability is preserved relative to the transported check.
- Rejected and accepted accumulation are equal at first order and very different in consequence. The best check spacing moves from sparse at low noise to dense at high noise; checking pays at moderate noise and not at high noise (example sweeps).
- A necessary mathematical condition for concurrent verification: the gate generator commutes with the check observable.

## Negative results

A Z-type fault is invisible to ZZ, and through a logical X rotation a logical Z fault becomes a mix of Z and Y, so it is no longer a Pauli. Physical concurrency is unresolved. The status table in the page lists physical nondestructive implementation as unresolved and advantage as unestablished.

## Corrections

(1) "Z-type errors commute through everything" was too broad. (2) The V0.5 chain model treats a fault as a Pauli frame that stays a Pauli, which is exact only for idle and Clifford segments. (3) The CNOT Hadamard is compatible with a moved check, not incompatible with parity. See [Errata](../errata.md).

## Limits

Six implementations of four logical operations, not a complete map; the transported-check claim shows a valid check exists, not that its extraction is cheap, fast or available; nothing about physical cost or timing.
