**Status: working development record, 2026-11-27. Index page for an original checkpoint.** Original files: [README](../../../checkpoints/v0.1/README.md), [page](../../../checkpoints/v0.1/docs/tetragon-map-v0.1.md), [handoff](../../../checkpoints/v0.1/CODEX_HANDOFF.md), [code](../../../checkpoints/v0.1/code/tetragon_map.py).

## Question

Does an entangled configuration persist usefully under operations, when can one axis stand in for another, and what does switching between encodings cost?

## Model and assumptions

Same ideal model as [V0](v0.md), seven parts. The cost metric of section 8 uses illustrative numbers [ASSUMED], for example 99% transmission per interaction.

## Results

- A maximally entangled state can be treated as a stored 2×2 unitary; operations on either axis compose into one 2×2 unitary and the entanglement never changes [DERIVED].
- Substitution of one axis for another is true for a known configuration, for a restricted subspace (tested on coordinate subspaces), and generally not for the whole register [DERIVED].
- Over the 12 ordered two-vertex encodings (144 ordered pairs): edge to edge 64 pairs (24 single-axis, 8 local on both axes, 32 needing an axis swap), edge to diagonal 64 pairs (all need an entangling gate), diagonal to diagonal 16 pairs (12 single-axis, 4 local on both axes) [DERIVED].
- A break-even form for persistence is proposed: savings must exceed preparation plus conversion back plus maintenance, all in one metric [PROPOSED]. All three terms are unknown.

## Negative or sobering results

Persistence inside an entangled class is only ordinary composition of single-qubit unitaries, which a single qubit does with no entangled resource, so the entangled resource is overhead for that work. Switching between a product-type and an entangled-type encoding always needs an entangling step, with unknown data carried through it.
