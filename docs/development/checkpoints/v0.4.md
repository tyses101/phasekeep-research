# Checkpoint V0.4: the Buddy parity check, in its simplest form

**Status: working development record, 2026-11-27. Index page for an original checkpoint.** Original files: [README](../../../checkpoints/v0.4/README.md), [page](../../../checkpoints/v0.4/docs/buddy-verification-v0.4.md), [handoff](../../../checkpoints/v0.4/CODEX_HANDOFF.md), [code](../../../checkpoints/v0.4/code/buddy_checks.py).

## Question

If a Buddy tests a property of encoded information without reading the information, what does it detect, what does it miss, and does adding it make the whole computation more reliable?

## Model and assumptions

One diagonal-encoded Tetragon (|0⟩ = |00⟩, |1⟩ = |11⟩, even parity) and one auxiliary binary system (the ancilla). Ideal gates, then independent Pauli faults on one checkpoint. All noise values are [ASSUMED] sweep inputs. Working identifiers BUD-01 to BUD-04 label four studies; they are provisional.

## Results [DERIVED]

- BUD-01: two CNOTs onto the ancilla leave valid data unchanged; one flip gives ancilla 1; **one phase error is not detected**. The check turns flips into rejection; it does not correct them.
- BUD-02: of the 15 non-identity two-axis Paulis, both encodings detect 8, leave 6 as undetected logical errors and 1 harmless.
- BUD-03: a Z fault on the ancilla between the two CNOTs becomes an undetected logical phase error and a PASS report. An X fault on the ancilla causes a false FAIL on valid data.
- BUD-04: with flip noise only, accepted outputs are purer than the unchecked baseline exactly when the harmful ancilla fault rate is below 2x(1−x), where x is the flip probability per axis.
- PALADIN is introduced as a provisional name for physical hardware protection, kept separate from quantum-state evidence (see [Register of terms](../register-of-terms.md)).

## Negative results

In this model the Buddy never gives more correct results per run than the same encoding without it (later qualified: the statement is specific to rejection-based Pauli models, see [V0.5](v0.5.md)). A Buddy can lower reliability: with no data noise, a 1% harmful ancilla fault rate causes 1% false acceptance. Dephasing-dominated noise defeats it. Classical hardware diagnostics may not see an ancilla phase error.

## Corrections

The sentence about correct results per run is qualified in V0.5 section 3. See [Errata](../errata.md).

## Limits

Independent Pauli faults on one checkpoint; no correlated noise, leakage or repeated checkpoints; no physical Buddy, nondestructive parity read or cost figure.
