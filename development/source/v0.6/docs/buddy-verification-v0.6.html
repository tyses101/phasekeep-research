Status: working draft for review. Ideal-model mathematics and a stated Pauli-fault model only. Not part of Revision H and separate from pull request #1. Builds on version 0.5 (not repackaged); v0.1 to v0.5 stay as earlier checkpoints.

Evidence tags: DERIVED (checked by code/buddy_v06_checks.py inside the stated model), ASSUMED (a parameter or modelling choice, not measured), PROPOSED (an idea or a test, not done), UNVERIFIED (supplied or remembered, and not checked), MEASURED (none exist). Physical cost fields are deliberately empty because no defensible apparatus parameters exist (audit item A02).

Central research question (unchanged): Can deliberate geometric organization and controlled transformation of photonic entanglement improve the efficiency, controllability, reliability or continuity of equivalent quantum operations?

Program question: Can a photonic processor adapt its information geometry, verification requirements and physical execution routes in response to changing operational conditions, while achieving a measurable advantage over conventional architectures?

1. What was done

The question moved from "how well does a Buddy detect errors" to "does the way an operation is implemented decide whether a check is compatible with it". Six studies, 33 checks, one stdlib program, all ALL PASS (under a second). Same encoding as before: diagonal, |0> = |00>, |1> = |11>, check ZZ, parity ancilla.

PartStudyResult DERIVED

The Hadamard built from rotations generated by ZI and XX never leaves the code. The Hadamard built from CNOT, H, CNOT leaves it midway, and a fixed ZZ read there is amplitude-dependent. 2. How to read it

  • Exact within the model. Every noise value is an example sweep input, not a prediction.
  • A "class" below is always relative to a stated check. A fixed ZZ check is one choice. A transported check (the same property followed through the operation) is another.
  • Nothing here shows that a physical Buddy, a check during a gate, or any advantage exists.

3. Corrections and refinements to earlier statements

  1. "Z-type errors commute through everything" (my v0.5 reply) was too broad. A Z-type fault commutes with ZZ, so the ZZ check cannot see it. It does not commute with every computational operation. Through a logical X rotation by theta, a logical Z fault becomes cos(theta) Z_L plus or minus sin(theta) Y_L. It stays undetected by ZZ and stays a logical error, but it is a Pauli only when theta is a multiple of pi/2.
  2. A limit of the v0.5 chain model, not stated there: it treats a fault as a Pauli frame that stays a Pauli. That is exact for idle and Clifford segments and not exact for generic logical rotations. The v0.5 spacing comparison holds for Clifford or idle segments. For generic rotations the right measure is state-dependent overlap with the ideal output.
  3. The CNOT implementation of the Hadamard is not "incompatible with parity". Relative to a fixed ZZ check its midpoint is amplitude-dependent. Relative to the transported check it is a valid code with check Z on axis b. That is a different extraction circuit, and a different geometry (an edge) for that interval. It is compatible, restricted to a moved check.
  4. v0.5 section 9 said a PASS goes stale with the number of operations. That still holds. The within-circuit timing window of v0.4 is the same idea at one check.

4. Compatibility map (PART 1 DERIVED; physical cost unquantified)

Working analytical table, not a new subsystem or glossary term. All six implementations return the correct logical operation and end in the code (checked as code block equal to the target up to a global phase).

  • Class A keeps the odd-parity weight exactly 0 at every sub-step tested (10 per generator, 200 random inputs).
  • Class B leaves the code in a known, amplitude-independent way. A check that expects odd there learns nothing about the logical amplitudes. This is a classical frame update.
  • Class C gives an amplitude-dependent value for a fixed ZZ read. Reading it and keeping PASS leaves the wrong logical state: mean fidelity with the intended output about 0.5 over 2000 random states.
  • Changing the geometry. A CNOT that moves the diagonal code to span{00,10} makes the old check read odd with probability |beta|^2 and the new check on axis b read 0 for every input. Verification has to follow the new geometry.
  • Reading, not just the endpoint, is the new criterion for GEA: which implementation of an available transformation allows the check the machine can actually run. That use is PROPOSED.

The generator-built H needs a coupling between the two axes of one photon (XX rotation). Its cost is unquantified (v0.3: H from a diagonal encoding needs an entangling gate).

5. Check-sliding and its limits (PART 2 DERIVED)

  • The extraction unitary is exactly U_ext = P_even (x) 1 + P_odd (x) X_ancilla. It depends on the data only through ZZ.
  • An ideal check slides past a gate exactly when the gate commutes with ZZ, on arbitrary inputs including odd components. Tested: ZI and IZ rotations, XX rotation and the XX gate slide. A single-axis X, a single-axis X rotation, the CNOT and a single-axis Hadamard do not.
  • With faults, sliding is not equivalence. In a compatible sequence a check at position p detects a single flip exactly when the flip occurred before p. Moving a check later covers more of the sequence but is not the same check.
  • A CNOT forces the check to move, not slide. In a sequence with a CNOT the valid check afterwards is Z on axis b. A flip on axis a made before the CNOT is detected at every later position by the moved check. The same flip made after the CNOT is not detected, because axis a now carries the qubit. A flip on axis b is detected either way. A ZZ check left in place after the CNOT reads values from 0 to 1 on fault-free states, so it checks nothing.

6. Error propagation (PART 3 DERIVED)

  • The damage an error does (overlap of the faulty output with the ideal output) is the same however many unitaries follow. Propagation changes the form of an error, not its size.
  • Relative to the transported check, an error that was detectable stays detectable and an undetectable one stays undetectable, through every unitary step tested (all 16 two-axis Paulis, including CNOT and a single-axis Hadamard). Through steps that commute with ZZ, this is also true for ZZ itself.
  • A logical Z fault carried through a logical X rotation becomes cos(theta) Z_L plus or minus sin(theta) Y_L (checked for four angles). Undetected by ZZ.
  • Error propagation is a separate study from parity preservation. Interaction between them (a fault that changes form, and a check that has moved) is where the full Buddy accounting will have to be done.

7. Rejected versus accepted accumulation (PART 4 [DERIVED in the model])

Faults that are caught (ancilla X, loss) leave accepted-correct = (1 - g)^m and nothing wrong is accepted. Harmful ancilla phase faults leave accepted-correct = (1 + (1 - 2g)^m) / 2, tending to 1/2, and the rest are accepted and wrong. For small g the two remove the same amount at first order. The difference is that one wastes a run and the other delivers a wrong answer.

9. Conditions for concurrent verification (PART 6 [DERIVED necessary condition; physical concurrency unproven])

U_ext is exp(-i pi P_odd (x) P_minus), a function of ZZ and the ancilla only. For a gate generated by a Pauli string, the gate generator commutes with the check Hamiltonian exactly when it commutes with ZZ: ZI, IZ, ZZ, XX, XY and YY do, a single-axis X does not. When the generators commute, applying them together equals applying them one after the other. That is the mathematical starting condition for "check during the gate". It is not evidence that hardware can do it: the check and the gate still act on the same axes, and the parity interaction, its readout and its faults are not modelled.

10. On verifying the preparation (PROPOSED reading of the design idea, with limits that are DERIVED)

The design idea: verify the structure that every valid state in a geometry must have, without reading what was prepared. In this model that is the parity property: it holds for every logical 0, 1 or superposition, and the ancilla ends independent of the amplitudes (v0.4, v0.5). Operations that preserve it let the check move along the sequence without changing the ideal computation (section 5).

What it does not establish:

  • A wrong relative phase passes the parity check (v0.4).
  • Faults after a check are not covered by it (section 5). Moving a check changes what it covers. A hundred parity-preserving operations do not make one check at any position cover them all.
  • Preparing the diagonal encoding from product inputs needs an entangling step (v0.3), and a phase fault in that step is invisible to parity.
  • Verified state preparation, stabilizer states and quantum nondemolition measurement are established topics [UNVERIFIED, from memory]. The PhaseKeep question is whether adaptive geometry makes them cheaper.

13. Limits

  • Ideal unitaries and independent Pauli faults. No correlated noise, no leakage, no readout error, no timing inside a check.
  • Compatibility is classified for six implementations of four logical operations, two of them the Hadamard. It is not a complete map.
  • The transported-check claim shows a valid check exists at each point. It does not show that the extraction circuit for it is cheap, fast or available.
  • Spacing and productivity results are example sweeps at fixed other parameters, not a full grid.
  • Nothing about physical cost, timing or hardware.
